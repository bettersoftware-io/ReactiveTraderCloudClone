# @rtc/client-core-effect

**Effect core delivery rule:** whatever one event causes reaches subscribers in one turn — across members, not only within one stream (the burst rule above). Effect's default scheduler gives every fiber resume a microtask of its own, so a tile heard its price a turn before the flash that price causes (three renders per tick against two); `@rtc/client-core-effect` therefore runs every fiber on its own scheduler (`bridge/turnScheduler.ts`), and plain code there never calls the global `Effect.run*` — it uses a host's runner or the bridge's `interruptFiber` / `closeScope`, which releases a scope's ports synchronously before closing it (grep gate 49; §22 guarantee 6, §23 promise 9). A new Effect member that folds two or more ports takes them through `fromPort.merged([...])` and its sources (`portEvents`, `switchedPortEvents` for a changing set, `latestOfEach` for `combineLatest`, `firstPortEvent` for a one-shot query), never an Effect combinator that joins streams — `Stream.merge`, `flatMap`, `zipLatest` and kin cost about eleven fiber steps per value and promise no order across the ports (grep gate 51). State a member owns lives in a `SyncRef` (`bridge/syncRef.ts`), never an Effect `SubscriptionRef`: that one reaches a subscriber through a fiber per subscriber, a step after the commit (grep gate 50). A set of ports that changes (the roster's prices) is one `switchedPortEvents` group inside `fromPort.merged`, and a reader of part of a shared stream gets a `filterStream` view, not a fold of its own. A fold settles before its `subscribe` returns (`turnScheduler.settle()`), so what a port replays on subscribe arrives with the values the subscriber was handed synchronously (§22 guarantee 7, §23 promise 10).
