# Drawing Tools (3a: draw / select / delete) — Design

**Date:** 2026-08-05
**Status:** Approved
**Workstream:** TradingView tier, sub-project 3a. Sub-project 3b (drag-edit:
moving endpoints / whole drawings) is deliberately deferred to its own
spec → plan cycle, landing on this slice's hit-testing and handles.

## 1. Goal

User-drawn chart annotations in both web clients: **trendlines** (two-anchor
segments) and **horizontal levels** (one-anchor full-width lines), drawn with
the pointer, click-selectable, deletable. Anchors live in **data space**
(candle index + price) and project through the two existing seams —
viewport-x and `priceToY` — so drawings pan, zoom, and rescale with the
chart and are mode-correct under linear and log automatically.

## 2. Decisions locked during brainstorming (2026-08-05)

- **Two sub-projects:** 3a = draw + render + click-select + delete (this
  spec); 3b = drag-edit, later, own cycle. Drag-editing an existing drawing
  is the fiddliest gesture (handle grabbing vs pan arbitration) and ships
  separately.
- **Tool set:** trendline + horizontal level. The trendline is the real
  machinery; the hline reuses all of it.
- **Persistence:** in-memory, keyed by symbol, in a composition-root machine
  (one instance per app composition, living for the app's lifetime — not a
  module-level global). Reload clears. Consistent with
  chartType/indicators/panes/yScale.
- **State home:** a dedicated `EqDrawingsMachine` in client-core — NOT
  `EqWorkspaceMachine` (that machine is tabs/timeframe/chart-display state;
  annotation CRUD is a different responsibility that 3b will grow further).
  Draft state (line-in-progress) never enters the machine — it is view
  state in the gesture hooks, like `cursor` (ADR-005: DOM-edge-driven
  per-move computation stays at the view edge).

## 3. `EqDrawingsMachine` (`@rtc/client-core`)

Types declared locally (client-core must not import motion-core — the
`EqPaneId` doctrine):

```ts
export type EqDrawTool = "cursor" | "trendline" | "hline";

export interface EqDrawingAnchor {
  readonly index: number; // candle index, snapped to a center at commit
  readonly price: number; // unsnapped
}

export type EqDrawing =
  | {
      readonly id: string;
      readonly kind: "trendline";
      readonly a: EqDrawingAnchor;
      readonly b: EqDrawingAnchor;
    }
  | { readonly id: string; readonly kind: "hline"; readonly price: number };

export interface EqDrawingsState {
  readonly tool: EqDrawTool;
  readonly drawings: Readonly<Record<string, readonly EqDrawing[]>>;
  readonly selectedId: string | null;
}
```

Initial state: `{ tool: "cursor", drawings: {}, selectedId: null }`. A symbol
with no entry renders nothing.

Intents (each a Subject → patch pair, merged into one `scan`, the
`togglePane` pattern; every subject `.complete()`d in `dispose()`):

- `setTool(tool: EqDrawTool)` — sets the tool and clears `selectedId`.
- `addDrawing(sym: string, drawing: EqDrawing)` — appends to the symbol's
  list, sets `selectedId = drawing.id`, and reverts `tool` to `"cursor"`
  (draw one, then you're manipulating — TradingView's default). The `id` is
  generated by the caller at the DOM edge (`crypto.randomUUID()`), keeping
  the machine pure.
- `selectDrawing(id: string | null)` — click-select / click-empty deselect.
- `deleteSelected(sym: string)` — removes the drawing whose id is
  `selectedId` from the symbol's list and clears the selection; a no-op when
  `selectedId` is null or not in that symbol's list.
- `shiftAnchors(sym: string, by: number)` — adds `by` to every anchor
  `index` for that symbol (both anchors of a trendline; hlines have no
  index and are untouched). **Why:** a backfill prepend shifts every candle
  index — the same reality `shiftForPrepend` handles for the viewport; the
  gesture hook's existing prepend-detection seam calls this so trendlines
  keep pointing at the same candles. Without it a backfill page silently
  slides every trendline `N` candles.

Wired in `composition.ts` beside `eqWorkspace`; disposed with it. Exposed
through both bindings as `useEqDrawings()` (state + intents). Known blast
radius priced in: both bindings' `createViewModel`, the test doubles,
`viewModelFromWorld` (both contract registries), and the visual
`buildFakeViewModel`s.

## 4. Motion-core math (`drawingScene.ts`, new — pure, zero-dep)

Structural twins of the machine types (motion-core cannot import
client-core; they unify structurally, the `ChartKind`/`EqChartType`
precedent).

```ts
/** Pointer fractions → a data anchor: index by crosshairScene's snap rule
 * (round(viewport.start + xFrac·span − 0.5), clamped into the series);
 * price = yToPrice(scale, yFrac·100) — unsnapped, mode-correct. */
export function pointerToAnchor(
  xFrac: number, yFrac: number,
  viewport: ChartViewport, scale: ChartScale, seriesLen: number,
): DrawingAnchor;

/** Projects committed drawings into plot-% geometry. Trendline →
 * { id, kind: "trendline", x1, y1, x2, y2, selected }; hline →
 * { id, kind: "hline", y, selected }. x via the candle-center rule
 * ((index + 0.5 − start)/span · 100), y via priceToY. Off-viewport
 * geometry still emits (the SVG clips); `selected` items also carry
 * handle coordinates (the two anchor points; an hline's single handle
 * sits at x = 50). */
export function drawingScene(
  drawings: readonly Drawing[],
  viewport: ChartViewport, scale: ChartScale,
  selectedId: string | null,
): readonly DrawingSceneItem[];

/** Click hit-test in plot-% space: point-to-segment distance per item
 * (an hline is the segment y = const, x ∈ [0, 100]); nearest item within
 * `tolPct` wins; null otherwise. tolPct default 1.5. Documented limit:
 * %-space distance is anisotropic in pixels (the plot isn't square) —
 * acceptable for click-select; 3b revisits if handle-grabbing needs px
 * precision. */
export function hitTestDrawings(
  scene: readonly DrawingSceneItem[],
  xPct: number, yPct: number, tolPct?: number,
): string | null;
```

## 5. Rendering — `DrawingsLayer` (both clients, twinned)

One SVG element, sibling of `SvgPathLayer` inside the plot box:

- `<line>` per scene item (`vector-effect="non-scaling-stroke"`), stroke
  from existing CSS theme vars; the selected item gets a thicker stroke and
  two small handle circles (`<circle>`; an hline gets one). Handles are 3b's
  future grab points but are the correct *selected* affordance now.
- `data-testid="chart-drawing"`, `data-kind`, `data-selected` per line;
  handles `data-testid="chart-drawing-handle"`.
- Renders `null`/nothing when the scene is empty — zero nodes in the
  default state; each drawing costs ≤ 4 DOM nodes (line + up to 2 handles +
  the shared SVG root amortized), pinned by a contract assert.
- No CSS animations, no transitions, no rAF. Pointer events on the SVG are
  disabled (`pointer-events: none`) — ALL pointer logic stays on the plot
  wrapper's existing handlers; hit-testing is done in math, not DOM
  hit-testing, so the layer can never steal the pan gesture.

## 6. Gesture arbitration (both clients' gesture hooks)

The fork lives in the existing `startDrag`/`dragOrTrackCursor`/`endDrag`
trio; the hook gains inputs `(tool, onCommitDrawing, onSelectDrawing,
onDeleteSelected)` — slots, so the hook stays machine-agnostic:

- **Click threshold:** `CLICK_MAX_PX = 4` — a pointer-down→up excursion of
  ≤ 4 px (Euclidean, client coords) is a *click*; beyond it, a drag. One
  constant serves both branches below.
- **tool === "cursor":** pointer-down behaves exactly as today (pan drag,
  capture). NEW: on pointer-up within the click threshold, run
  `hitTestDrawings` at the click point and call
  `onSelectDrawing(idOrNull)` — select a line, or deselect on empty.
- **tool === "trendline":** pointer-down opens a **draft** in hook state
  (`{ a: anchor, b: anchor }`, b tracks the pointer per move); pointer-up
  beyond the click threshold commits via `onCommitDrawing` (id minted here
  with `crypto.randomUUID()`); within it, the draft is discarded (a stray
  click draws nothing). Escape cancels an open draft. **Draft projection:**
  the hook exposes the draft's two anchors; `CandleChart` wraps them as a
  temporary `Drawing` with the sentinel id `"draft"` and appends it to the
  `drawingScene` input, so preview and committed rendering share one code
  path; `DrawingsLayer` styles it via `data-draft="true"` (dashed stroke,
  no handles).
- **tool === "hline":** pointer-down commits immediately (one anchor is all
  it needs) — no draft phase.
- The crosshair keeps tracking in all modes (it is the aiming aid); wheel
  zoom, keyboard pan/zoom, double-click reset, and the navigator brush are
  untouched. `Delete`/`Backspace` in the plot's existing `onKeyDown` calls
  `onDeleteSelected()` when the tool is `"cursor"`.
- Pointer capture semantics are unchanged — the draft rides the same
  captured pointer today's pan drag uses; the pane-hover and
  button-bypass special cases are untouched.

`CandleChart` wires the hook's slots to `useEqDrawings()`'s intents and
passes `drawingScene(...)` output (committed + draft) to `ChartPlot` →
`DrawingsLayer`. The prepend-detection branch in the gesture hook (the
`shiftForPrepend` block) additionally calls `shiftAnchors(sym, grewBy)`.

## 7. Tool pills

A third pill group in the chart-head pill row, after the LOG pill and a
`.divider`: `TL` and `H-LINE` (`data-testid="chart-draw-pill"`,
`data-tool`, `data-active`). Clicking an inactive pill selects that tool;
clicking the active one reverts to `"cursor"`. Driven by
`useEqDrawings()`'s `tool`/`setTool` through `EqChartHead` — same wiring
shape as the LOG pill.

*(Amended 2026-08-05 at final review: the pills shipped as the row's last
group, after TimeframePills and without a divider — judged the better
placement at the app-equities golden eyeball; the spec's original "after the
LOG pill + divider" wording is superseded.)*

## 8. Testing

- **motion-core units** (`drawingScene.test.ts`): pointer→anchor→scene
  round-trip in BOTH scale modes (the segment lands where the pointer was);
  anchor+N shift renders at the same time-position after a simulated
  prepend; hline spans x 0→100 at `priceToY(price)`; hit-test table
  (on-segment within tol, near-miss reject, nearest-of-two, empty → null);
  off-viewport anchors still emit finite geometry.
- **machine tests**: every intent's patch (add auto-selects + reverts tool;
  setTool clears selection; delete no-ops when nothing selected;
  shiftAnchors moves only the target symbol's trendline indices, hlines and
  other symbols untouched); per-symbol isolation.
- **contract (shared, both frameworks)**: pills set tool + `data-active` +
  active-pill-again reverts to cursor; a synthetic pointer sequence (the
  crosshair specs' stub-rect `setPointer` machinery, extended with
  down/move/up) draws a trendline → exactly one `chart-drawing` whose
  geometry matches an independent `drawingScene` computation; click-select
  sets `data-selected`, empty-click deselects; Delete removes it; switching
  symbol hides the drawing and switching back restores it; **node budget**:
  zero drawing nodes when none exist, ≤ 4 per drawing.
- **visual**: ONE new scenario `equities/chart-drawings` — a trendline + an
  hline with the trendline selected (handles visible), forced-state wrapper
  (literal drawings via the fake view-model seam, no gestures), 10 themes;
  react writes, solid asserts. Drawings are opt-in DOM ⇒ **zero existing
  stems change**; the sync PR is 10 stems.
- **e2e**: one journey — `TL` pill → real pointer drag on the plot → a
  `chart-drawing` appears → click it → `data-selected="true"` → press
  Delete → gone. Real-browser pointer capture is precisely what jsdom
  cannot witness (the `startDrag` button-bypass comment's own lesson).

## 9. Perf & motion

Zero new animations/transitions/rAF; the overlay is static SVG re-rendered
discretely with the viewport like every other layer, and absent entirely
when no drawings exist. Freeze/power-saver untouched.

## 10. Out of scope (recorded)

- **3b — drag-edit**: endpoint/whole-line dragging, handle grab arbitration
  vs pan, px-precise hit tolerance. Next sub-project; STATUS.md carries it.
- Snapping the price to OHLC values, ray/extend modes, labels on drawings,
  more tool kinds, mobile/RN drawings, persistence — all explicitly not in
  3a.
- Timeframe scope: anchors are candle indices within the selected
  timeframe's series, and drawings are keyed per symbol only — a drawing
  made on one timeframe projects onto unrelated candles on another; 3b
  inherits this recorded limitation, it is not a bug.
