# B3b brain indicators: rulings made during execution

These are the decisions taken while the [plan](2026-10-27-b3b-brain-indicators.md) ran (subagent-driven, 2026-10-27). They come in addition to the planning rulings R1–R7 in the plan itself. Each entry gives the decision, the reason and what it costs if it turns out wrong.

## Before execution (from the preflight scan)

- **A. Placeholder budget in the adapter between Tasks 2 and 3.**
  - Decision: Task 2 made `WsJarvisAdapter.parseAvailability` compile with `budget: null, demo: false`. Task 3 then replaced it with `parseBudget`.
  - Why: every commit keeps typechecking.
  - Cost if wrong: none, because Task 3 overwrites the placeholder.
- **B. The pill copy follows spec §4.3, not the plan's example.**
  - Decision: `describeBrainPill` returns `Haiku 4.5 · $0.14`, with no "left". The ▾ caret is a separate `aria-hidden` glyph in the component.
  - Why: the spec is binding over the plan.
  - Cost if wrong: a one-word copy change plus goldens.
- **C. Escape in the pill menu (superseded).**
  - Decision: the menu's handler called `preventDefault`, and both overlays' `closeOnEscape` skipped events already marked handled.
  - Superseded by the final-review ruling below: the claim that this "works whatever the listener order" was wrong.

## During the tasks

- **D. The readout's reset time is derived, not hard-coded.**
  - Decision: "back at HH:MM UTC" comes from `budget.resetsAtMs` through the same helper as the switch line (`formatGateResetTimeUtc`).
  - Why: one formatter. The daily reset is UTC midnight, so the copy still reads 00:00.
  - Cost if wrong: a one-line change.
- **E. Local goldens are committed with the UI change.**
  - Decision: the darwin-arm64 `react-local` goldens for the affected Jarvis and Preferences scenarios are regenerated and committed on the branch. The x86 `react/` set is regenerated by `update-visual-goldens.yml`.
  - Why: the repo commits local goldens alongside UI changes.
  - Cost if wrong: drop a commit.
- **The meter width is an inline custom property.**
  - Decision: the meter is sized with `--meter-fill` and the CSS reads `width: var(--meter-fill)`.
  - Why: a lint rule bans literal `style={{ width }}`. The behaviour is the same and there is still no motion.
  - Cost if wrong: none.
- **The pill menu always offers Scripted.**
  - Decision: the menu lists `scripted` plus `state.brains`, the same rule as the Preferences picker. The plan had said "filtered to `state.brains`".
  - Why: the two pickers stay consistent.
  - Cost if wrong: one filter line.
- **Only changed goldens are committed.**
  - Decision: the `jarvis/panel-*`, `jarvis/status-chip-*` and `jarvis/orb-attention` regenerations were left out.
  - Why: they differed by 160–2239 px of regeneration noise, not by this branch's change.
  - Cost if wrong: those goldens get regenerated later.

## From the final whole-branch review

- **Escape works from anywhere (replaces C).**
  - Decision: while the menu is open, a capture-phase `document` keydown listener closes it on Escape and returns focus to the pill. Opening the menu focuses the checked item.
  - Why: Safari and macOS Firefox do not focus a clicked button, so Escape reached the overlay and closed it. Ruling C also depended on listener order.
  - Cost if wrong: handler rework.
- **Readout colours.**
  - Decision: the warning tone uses `--accent-aware`, because `--warn` was never defined in the app. The normal tone first moved to `--text-secondary` (then `--accent-primary`, below), and reply tags keep `--text-muted`.
  - Cost if wrong: one CSS token plus goldens.
- **Light skins: the normal-tone readout uses `--accent-primary`.**
  - Finding: on the light skins the `--text-secondary` readout was nearly invisible, because the overlay's backdrop is dark there.
  - Decision: parked to the user, who chose (2026-10-29) the status line's `--accent-primary`, so the readout matches the line above it in every skin.
  - Cost if wrong: one CSS token plus goldens.
- **The Preferences row counter now counts the Reset row.**
  - Decision: the column-balance helper counts the "Reset workspace layout" button, and the Jarvis carve-out is 6.
  - Why: the old carve-out of 5 and the uncounted Reset row were two errors that cancelled each other.
  - Cost if wrong: one test-helper line.
- **Old servers still tag narrator turns with the brain asked for.**
  - Decision: left as is.
  - Why: it happens only with a pre-B3b server and is cosmetic.
  - Cost if wrong: narration shows a Haiku tag until the server is deployed.
- **The final reviewer's "declined to judge" list is accepted.** Its items:
  - own-key lines wait for B3c;
  - the meter width may change mid-turn, without animation;
  - a reply tag may change once, when the brain frame arrives;
  - React Native is out of scope;
  - the server and both web clients deploy together;
  - the switches sit after the narrator row.
