## Up-front rulings that changed shape in execution

- **Ruling 8 (`followPort`: no seed peek on a keyed wire stream)** — held; R-3b draws its boundary: it does not reach presenter-owned cells.
- **Ruling 9 (`orders()` as a one-shot, newest refresh wins)** — held, and the Effect core's wording was corrected by measurement. The plan said the refresh `PubSub` subscription "must exist from the run's first step" (`merge`, not `concat`). MEASURED on `effect` 3.22.2: with `merge` a refresh published within ~2 microtasks of the period forking is LOST (from 3 on it is heard); `concat` loses one microtask more. What makes the window harmless is that in EVERY lost case the first `orders()` query had not started yet, so the initial query observes the update anyway. `merge` is "narrower, not absolute"; the comment and README now say so.
- **Ruling 10 (`scopedPortStream`)** — held without its fallback. MEASURED: `Stream.unwrapScoped` keeps its scope open for the whole consumption of the stream and re-evaluates `Effect.scope` per run, so the stream is lazy, two runs are two port calls, and an interrupt releases the source.
- **Ruling 11 (`candleSeries`'s two knowing oddities)** — held, and the second is now measured rather than assumed: a page landing AFTER a new warm period has started IS stitched into that period — in the RxJS core too (`older$` is one `BehaviorSubject` per key; the `defer` resets only its value). Parity kept in both siblings; recorded, not fixed.
- **Ruling 13 (the singletons are app-lifetime)** — extended by R-7a.
- **Ruling 15 (`createRunSlot` owns the guard)** — held. The count in STATUS was wrong: FOUR superseding machines per core, not five (`rfqCountdown`, `rowHighlight` and `staleFlag` hold one lifetime controller and never supersede). The plan's claim that the Effect slot's out-of-band rethrow is "new but unreachable" was TOO STRONG: a throwing `onRedirect` (wrapped in `run.guarded(Effect.sync(...))`) becomes a Die that now reaches `reportOutOfBand`. Shipped deliberately — it CONVERGES the Effect core onto what the async core always did (`spawn` + `reportAsync`; slice 2 ruling 8).
- **Plan-level correction:** Task 1's dispatch needed P2's note; a future plan whose Task 1 adds a domain export consumed by client-core in the same task should schedule the domain rebuild explicitly.

## What the reviews caught

Every per-task and whole-branch review found something real, and — as in slices 2 and 3 — almost all of it was the same class: **a test that reports an absence as a clean reading.**

- **PR R, Effect `runSlot.test.ts`:** the token guard's skip path and the interrupt filter's silent side were never executed by any test; the supersede case passed with the guard deleted while its comment claimed it proved the guard. Fixed by driving `write`/`guarded` directly through `runSync` with no fiber in play (plus a positive control) and a self-interrupting build; `runSlot.ts` 80% → 100% branches.
- **PR A, the candle contiguity filter** in `stitchCandles` was unwitnessed REPO-WIDE: in every case — the new fold test, the contract case, and a pre-existing test named for the guard — the dropped candle's time also existed in the base, so dedupe-by-time alone produced the same array. Now pinned in the fold test (RED proven with the filter deleted) and in the contract.
- **PR B, async:** two "intent after dispose is ignored" tests read a cold `state$.getValue()` after the keep-warm had been released, which returns the construction-time default whether or not the intent applied — the only coverage of the `disposed` guard. Rewritten subscribe-first; RED proven (4 failures with the guard removed). A "superseded run's late update is ignored" test could not reach `run.ifCurrent` (the relay unsubscribes first); retitled to the withdrawal it pins.
- **PR B, Effect:** the same supersede shape; a "parent scope ending disposes the machine" test that the RxJS keep-warm made vacuous (the implementer's FIRST rewrite was vacuous too, and it said so: the discriminating probe is the keep-warm RELEASE); a missing interrupted-page test; `{ switch: true }` unpinned (RED proven with it removed).
- **Both siblings:** `loadingOlder$` / `historyExhausted$` built a fresh stream per call where RxJS returns the same `BehaviorSubject` per key; memoised per key.
- **PR B, final whole-branch review (docs):** three doc statements read false against the code — the claim that `ordersBlotter`/`orderTicket` both route through `createRunSlot` (only `orderTicket` does; `orders$` supersedes its own query instead), the STATUS residual claiming the base app's orphaned `eqWorkspace` "peeks it once and is otherwise unused" (it also keeps the port warm via `warmReplay()` and is handed `seed$`, and `jarvisDriver`'s `knownSymbols$` reads the same base `watchlist$` on purpose), and a stale pending-suite-count history (37 at slice 3's merge, not 38 — the 38th, `layoutPresets`, joined with Dockview Phase 6b). Fixed in ADR-006, §22 and STATUS.md. The same review recorded nine cross-core asymmetries no suite pins, now in ADR-006 "Decided in slice 4".
