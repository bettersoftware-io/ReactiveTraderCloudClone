## Rulings made during execution

1. **R1 — the registry key ships with the member, not with the suite.** Task 1 also edits `packages/core-contract/src/registry.ts`: `"machines.rfqCountdown": null` into `CONTRACT_SUITES` (after `ticketSubmission`) and `"machines.rfqCountdown"` into `PENDING_SUITES`; Task 3 then replaces the `null` with the suite and removes the pending entry. Why: `CONTRACT_SUITES` is an exhaustive `Record<ContractMember, …>`, so the moment `MachineFactories` grows a member the package does not compile — the plan put the key in Task 3 while telling Task 1 to build `core-contract` and run `parity.test.ts`, which would have left the seam gate red between two commits of one parallel wave and blocked Task 2. `PENDING_SUITES` therefore ends at 37 as planned, but by 45 − 8 rather than the plan's 44 − 7. Cost if wrong: one line moved between tasks.
2. **R2 — the harness's one-shot FIFO stays `unknown`-typed behind casts.** The port-side `as Observable<number>` / `as Observable<void>` casts in `scriptedPorts.ts` (one `createPendingQueue` serving five differently-typed methods) are accepted as plan text; a reviewer finding against them is answered by this ruling unless it names a runtime consequence. Why: the alternative — a typed queue per kind — is five copies of the code ruling 14 exists to collapse. Cost if wrong: a typed-per-kind queue later.
3. **R3 (process) — implementers run on `sonnet`, commit by pathspec, never a bare `git`, never a background command, never a repo-wide build; only Task 1 runs builds in the PR A wave.** Why: the two tasks share one worktree, and a `--filter`ed `tsc --build` also rebuilds what it references. Cost if wrong: a stray commit on the primary checkout (recovery recipe in memory `subagent-cwd-pins-to-primary-not-worktree`).
4. **R4 — the `rfqCountdown` wiring test freezes `Date.now()`.** `composition.machineFactories.test.ts`'s new case read `Date.now()` twice unmocked and asserted an exact `300`, failing roughly 1 run in 300; the sibling `RfqCountdownMachine.test.ts` already freezes the clock with `vi.spyOn`, so the fix is to do the same and keep the exact assertion rather than loosen it. The plan's snippet was wrong. Cost if wrong: none (test-only).
5. **R5 — delivery multiplicity of a same-tick burst is NOT contracted.** The `rfqs` suite's first draft pinned how many values a synchronous burst of port events produced. Slice-2 discipline is exact arrays only across settle-separated emissions; a burst asserts `.at(-1)`. The fix settles between the emissions that must be observed separately and asserts deltas across settle-separated pairs; `quotesAfterRfq` is asserted explicitly, because reference-dedupe on rfq events IS contracted (up-front ruling 5). Why: the suites are the contract for two ports that did not exist yet, and a fiber- or `Store`-backed core legitimately conflates a synchronous burst — pinning multiplicity would have failed a correct implementation. Cost if wrong: none; the teeth are preserved by the settle-separated deltas.
6. **R6 — the `rfqTile` tick census across the bulk advance stays** (recorded, not fixed). If PR B (#800) trips on it, keep both endpoints and the first two deltas and drop the census; never loosen the endpoints. It did not trip: both cores held it on the first run. Cost if wrong: one assertion edit in PR B (#800).
7. **R7 — `rfqCountdown` pins stillness by emission count and the exact post-dispose value** (`[TOTAL_MS]`) — a knowing exception to "absence is not a reading", because a pure timer has no port-side witness to count instead. All three cores satisfy it (RxJS completes; `Store` and Effect drop equal states). Cost if wrong: an assertion edit.
8. **R8 — burst multiplicity on `rfqs.events$` IS contracted for an attached subscriber.** `events$` is an event stream (it feeds `AnimationDirector` intents), so a dropped event is a lost fact, unlike tick conflation on a state-derived stream; the pin stays, with a comment saying why it is the exception to R5. Cost if wrong: PR B (#800) adds a `settle()` between the two emits.
9. **R9 (process) — the Task 4 and Task 5 implementers run NO builds.** The controller built all 24 dists once before dispatching (check-dist clean); vitest resolves each sibling's own `src`, and the contract runner uses the prebuilt `core-contract` dist. The controller builds again at the Task 6 gauntlet. Why: Tasks 4 and 5 run in parallel in one worktree, and two `--filter` builds can truncate a shared `.d.ts`. Cost if wrong: a rebuild.
10. **R10 — the Effect `rfqSubmission`'s `onRedirect` guard stays although the race is measured unreachable.** On `effect` 3.22.2 a fiber resumed from `Effect.sleep` processes the forked interrupt before its next step, so a superseded run whose redirect timer already fired cannot reach the callback today. The guard stays because the invariant belongs to the run token the machine owns, not to the scheduler's delivery order. Cost if wrong: three lines.
11. **R11 — the async `rfqSubmission` checks `signal.aborted` before `onRedirect` and before the trailing `editing` write, so both cores leave `confirmed` when the consumer disposes inside the redirect callback.** Why: the shipped unmount-on-navigate shape must not diverge by core. Cost if wrong: two lines.
12. **R12 — the Effect `events$` equal-object conflation is recorded as a cross-core asymmetry, not re-engineered.** Why: every shipping producer builds a fresh object per event. Cost if wrong: a non-conflating mirror later.
13. **R13 — the ADR/§22 receipts scope the run-token sentence to the Effect core.** Why: the async core has no run token; a receipt must describe the code. Cost if wrong: none.

## Up-front rulings that changed shape in execution

- **Ruling 2 (`rfqCountdown` joins `MachineFactories`)** — unchanged in substance, extended by R1: the registry and `PENDING_SUITES` entries belong to the commit that adds the member, not to the commit that adds its suite.
- **Ruling 11 (the countdown reads the clock once)** — held for the machines; the *wiring* test it implied was wrong, which is R4. Recorded alongside it: the `rfqCountdown` seed is symmetric in its two arguments (`creationTimestamp`, `totalMs`), so no wiring test can detect a swapped pair — `client-core`'s own case shares the blind spot. Recorded, not fixed; a witness needs asymmetric fixture values. Cost if wrong (added when recorded): a swapped pair ships until a suite drives the two values apart.
- **Ruling 12 (the `rfqTile` suite pins ticks, not the 100-element array)** — held, and R6 fixes the boundary of how much census is worth keeping.
- **Ruling 13 (dispose semantics as slice 2 recorded them)** — R7 is the knowing exception: `rfqCountdown` pins the exact post-dispose value where the slice-2 ruling leaves a still-attached subscriber uncontracted.
- **Ruling 10 (a superseding call cancels the run in flight)** — held; R10 extends it from the state writes to the `onRedirect` callback, which the plan's shape did not cover.
- **Ruling 14 (`createPendingQueue`, one helper used four times)** — held, at the price R2 accepts.
- **Plan-level correction (PR A final review):** the plan's `PENDING_SUITES` arithmetic read "44 → 37"; the correct figure is **45 → 37**, because the slice's own new member is pending from the moment it exists (R1). The plan's Task 3 Step 8 line, its commit-message line and its self-review arithmetic are corrected in place.
