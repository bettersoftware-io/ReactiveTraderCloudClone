# The Ops rename (B2c PR 1) — rulings

Plan: [2026-10-24-ops-rename.md](2026-10-24-ops-rename.md) · Spec: [../specs/2026-10-18-b2c-users-panel-design.md](../specs/2026-10-18-b2c-users-panel-design.md) §3

These are the decisions the controller took during subagent-driven execution, each with what it costs if wrong.

## Rulings

1. **No layout-payload version bump** (planning, departs from spec §3.2). The workspace-layout parser already fails closed on an unknown tab key, and on a tree leaf that is neither in the seed nor docked. A pre-rename `{ v: 1, tabs: { …, admin } }` therefore reads as no saved layout. A test pins it with the real pre-rename shape (`fx, credit, equities, admin`).
   - **Cost if wrong:** an old layout half-applies.
2. **The `react-local/linux-arm64` golden set is only renamed, never regenerated.** STATUS records it as a partial bucket (~95 files), stale since 2026-07-19 and slated for deletion. Its tab-bar shots still say "ADMIN".
   - **Cost if wrong:** that bucket stays stale. It gates nothing in CI.
3. **The local no-update visual assertion is scoped** to the regenerated tab-bar scenarios plus the renamed `ops/*` ones. Pre-existing local drift unrelated to this PR is recorded in STATUS.
   - **Cost if wrong:** unrelated local drift stays unnoticed. CI's x86 set is the gate.
4. **The `react-local/darwin-arm64` tab-bar shots (28 scenarios) were regenerated with this host's text-rendering drift**, which a pixel audit showed goes beyond the label. That set was last made on 2026-10-06, and this Mac now runs macOS 27. The 12 regenerated scenarios without a tab bar were restored byte-for-byte. The commit message states the drift.
   - **Where the label-only proof lives:** the x86 `react/` set, regenerated by `update-visual-goldens.yml` in its pinned container and pixel-audited by the controller (below).
   - **Cost if wrong:** the local set is mixed-vintage, which STATUS already records as drifting.
5. **The 28-scenario golden pattern** is
   `(app/[^_]*__|app/fx-(light|system)$|layout/fx-docked-panel(-dockview)?__|shell/view-menu-(open|layouts-dockview)__|chrome/header__)`.
   - The pinned-skin scenarios `app/fx-light` and `app/fx-system` have no `__<skin>` suffix. The plan's first pattern missed them.
6. **The orphaned per-tab keys of the old Admin tab are PR 2's to handle.** These are `rtc-dock-layout-admin` and `rtc-layout-presets-admin`, the Dockview default engine's blob and the tab's presets. This PR leaves them unread. PR 2 makes `admin` a tab again, so its plan gains a step: a Dockview blob holding none of the tab's seed panels restores the seed. Old admin presets read as the codec's existing "unreadable" entries.
   - **Cost if wrong:** the administrator's View menu lists unreadable old presets until they are deleted.

## The x86 golden audit

`update-visual-goldens.yml` (run 40125389422, auto-commit `eb5ba7a71`) regenerated 262 PNGs: 26 scenarios in 10 skins, plus the two pinned-skin scenarios. Every one of them is in `react/`. A per-pixel comparison against the previous commit found:

| Result | Files |
|---|---|
| Size changed | 10 |
| Differences only in the header band (top 70 px) | 208 |
| Differences below the header band | 44 |

- **Size changed.** All ten are `chrome/header`, which is 18 px narrower because OPS is shorter than ADMIN.
- **Below the header band, 32 files.** Every pixel there differs by 1–3 levels of 255: invisible anti-aliasing beside the narrower label.
- **Below the header band, 11 files.** These are `shell/view-menu-open`. It has 60 differing pixels at y≈500–600, which is the View menu's own "Admin" → "Ops" entry.
- **Below the header band, 1 file.** `terminal-light/app-equities-instances-dockview` has the label change plus the sliding active-tab underline under the chart and Watchlist tabs, captured at a different point of its animation.
  - This is unrelated to the rename. The same scenario family flaked once locally.
  - **Follow-up:** pin that underline's capture frame (see "capture determinism" in the visual-tier docs).
