# B3c bring-your-own keys: rulings

Every ruling the controller made while building [the B3c plan](2026-11-01-b3c-byo-keys.md), kept because the working ledger is git-ignored. Each has what it costs if wrong. PR 4 appends its own at the end.

Spec: [B3 design](../specs/2026-10-25-b3-ai-metering-byo-keys-design.md).

## Before building (plan scan)

1. **The fake check is passed in, not read from the environment.** `ConnectionOwnKey` takes its `verify` function as a dependency, and `index.ts` passes the fake one when `RTC_JARVIS_FAKE=1`. So `verifyOwnKey` reads no environment and stays pure. Wrong: one signature change.
2. **Task 8 may touch `core-api` and every `IWsAdapter` implementation or fake that fails typecheck.** The plan's interface requires it. Wrong: no cost.
3. **`jarvisBrainTakesEffort` arrives in Task 10.** Until then the server's effort check stays on the model id. Wrong: one small server edit in PR 3.
4. **The real-key run in Task 14 stops and asks the user.** It is security-sensitive and the spec requires a hand run. Wrong: no cost.

## PR 1: the policy

5. **The deploy guard is `check-csp --dist`, not the brief's literal grep.** The bundle must name a host that `connect-src` allows. The literal grep already runs just above it, so both guards run. Wrong: no cost.
6. **The spec file sits under `tests/browser/playwright/` and the scenario under `tests/browser/scenarios/`.** That is the repo's layout; the plan's path was wrong. Wrong: no cost.
7. **The devtools inline guard moved into a module.** This is outside the brief's file list, but the brief says to fix the code. Wrong: a small cost.
8. **`?relay=<ws-url>` on the deployed `/devtools/` is blocked by `connect-src`.** React Native inspection runs from the local dev server, which sends no policy. Widening `connect-src` to any WebSocket host would undo the policy. Wrong: a person has to run devtools locally to inspect React Native.
9. **A deploy smoke that pipes `curl` into `grep -q` under `pipefail` may see curl exit 23.** Real but low risk, because headers arrive in one write. Wrong: one false red after a good deploy; re-run the smoke.
10. **Adjacent doc comments in `Csp.ts` are left alone.** Cosmetic.

## PR 2: the server

11. **The fake path is its own function, `fakeVerifyOwnKey`.** `ConnectionOwnKey` takes the verifier, the limiter and the caller id. The OpenRouter check uses `/api/v1/key` until Task 14 confirms it. Wrong: small.
12. **The same key sent again after `unreachable` or `limited` makes a new check.** After `accepted` or `checking` it only updates the cap. Read literally, the brief's rule left "Try again shortly" with no way out. *Superseded in PR 4 (item 61): after `refused` it checks again too.* Wrong: one extra check per retry, bounded by the limiter.
13. **The cap is read once per turn.** Wrong: small.
14. **The own client does not inherit the operator's Anthropic environment.** Wrong: small.
15. **A successful check refunds the limiter's charge.** Reconnects are free and only failed guesses count. Wrong: small.
16. **Anthropic's low-credit 400 maps to the "out of credit" refusal now,** matched on the error's `credit balance` text without logging it. The status and text are from memory, so Task 14's real-key run confirms them. Wrong: that case keeps the generic copy.
17. **The per-socket cap and per-socket key are accepted.** Spend is per person, the limit is per socket, the most generous tab governs, and Remove in one tab leaves the other live. None spends beyond the person's own choice. The server has no ping, so "gone when the socket closes" can lag by minutes. Both are recorded in `security.md` and the plan. Wrong: a person is surprised by a second tab.
18. **A topped-up key stays refused on its connection.** Remove then save again clears and rechecks, and a reconnect rechecks. *Superseded in PR 4 (item 61): the same key sent again after a refusal is checked again, and "Try again" shows for it.* Wrong: one extra click.
19. **A non-refundable hourly ceiling sits beside the refundable guess limit.** Tabs reconnecting normally stay under it, and a flood stops. Refunds keep the guess limit doing its own job. Wrong: a very flappy client reads `limited` until the hour rolls.
20. **A ceiling that drops a working key on that connection until the hour turns is accepted.** It takes far more checks than normal use makes. Wrong: a person re-saves their key next hour.
21. **The full-stack smoke asserts the own brain's stamp on its reply.** Task 6 promoted this into its fix round: a regression to scripted would otherwise pass the only live witness of own routing. Wrong: a line of test.

## PR 3: the clients

22. **A stored own brain whose model left the list reads as `scripted`, not as the default.** This overrides the plan's Task 2 sentence. The default is a house brain, and a person who chose their own key must never be moved quietly onto the house's. Wrong: one scripted turn before the person re-picks.
23. **A preferred own brain whose key is `unreachable` or `limited` has its own readout row.** `Scripted · couldn't reach <Provider>` and `Scripted · too many key checks`, both warnings. The aim is that nobody is unsure whether a real model answered. Wrong: two short strings.
24. **The owner of a key is `state.user.email`.** Auth state carries no username, every core already folds the email, and the server normalises it. Wrong: one line per core plus fixtures.
25. **After any sign-in with a known owner, the transport holds that owner's key or nothing.** The controller sends a clear whenever it restores nothing, because the transport outlives a composition. A clear on a closed socket is local memory only. Wrong: one no-op call per sign-in.
26. **The limit on a saved key is editable in place.** The spec calls it adjustable. Wrong: one small control.
27. **The readout line for someone who chose scripted never says their daily limit is used.** Wrong: small.
28. **The Effort control is greyed out for Haiku, the default brain.** This is true on the server, which omits effort for Haiku. It needs the user's sign-off at the golden review. Wrong: the control looks missing.
29. **An own-shaped string never falls to the house default.** Task 5 promoted this into its fix round: it touches the rule that a person's choice of key is never quietly moved onto the house's. Wrong: a line.
30. **A string turn id in a key frame is not logged.** Task 5 promoted this too: a frame carrying a key must leave nothing of itself in a log. Wrong: a line.
31. **The provider list is one list.** A new provider in PR 4 would otherwise delete stored keys as malformed. Wrong: a line.
32. **A storage read failure keeps the key.** A transient `getItem` failure used to delete a valid value. Wrong: a line.
33. **The domain import cycle is fixed, not parked.** `JARVIS_PROVIDERS` and `isJarvisProvider` moved into `jarvisOwnModels.ts`, because `pnpm check:deps` fails CI. Wrong: a line.
34. **The hook-to-wire path has no client unit test.** The full-stack browser case covers it: it saves a fake key, sees it accepted, reloads, runs a reply on the own brain, signs out and finds nothing in storage. Wrong: a break there shows in that case, not earlier.
35. **Own-key failures that touched a constraint were fixed in the Task 7 round, not deferred:** `own && exhausted !== null`, so the switch line names the budget that was spent, and `budgets` as a required parameter, so no caller can leave the choice of budget out. Both restore a guarantee that task claims. Wrong: small.
36. **The key member ends with its composition.** `OwnKeyFold.stop()`, called from each core's release, makes the intents do nothing, because a presenter still held after a hot swap would send the old owner's key or clear the store under the next composition. Wrong: small.
37. **Smaller Task 9 corrections went in the same round:** a comment that still said username, a doc comment that had moved off its function, and the skill's member count. Wrong: small.
38. **The transport checks whose session the shared store holds, by account.** Before a socket opens on its own (a reconnect, a return from an idle close), before a key frame, and when `connect()` finds a socket live, `WsAdapter` compares the stored session's account (the user's email, the identity the fold uses) with the one its socket opened for. Missing, or another account, reports `sessionEnded()` and opens nothing, so that tab signs out and the fold wipes. Chosen over a storage-event port across three cores: it is one seam, and it closes the second-tab hole. Wrong: a tab is signed out at reconnect after another tab signed in as another account, which is safe.
39. **A new token for the same account is taken, not a move.** An unlock rotates the token under a socket that stays open, in this tab or another, so comparing raw tokens signed both tabs out at the next drop. The first fix wave compared raw tokens and adopted only this tab's own writes; the extra round replaced that with the account comparison. Both clients hand the adapter the session store itself, so the token and the account come from one read; an adapter given only a token function still compares raw tokens: the safe side. Wrong: a person signs in again after an unlock.
40. **A live socket is checked too.** A hot swap composes over the socket the last composition left, and its key fold runs ahead of its transport gate, so the next account's remembered key would go out on the last account's socket. A key frame is refused on a socket the session moved off, and the gate's `connect()` closes it and ends the session. Wrong: a tab signs out at a hot swap after another tab switched account, which is safe.
41. **Every core listens for an ended session before its transport gate connects.** The gate's first `connect()` after a hot swap can end the session from inside the call, and `sessionEnded()` is hot, so the RxJS core, which subscribed after the gate, stayed signed in over a closed socket. It now subscribes first, as the other two already did. Wrong: none; the order is free.
42. **A tab that ends its session clears the shared session store and the remembered key.** After tab A switches to another account, tab B's check signs B out, which removes A's new session and A's remembered key too; A signs out at its next reconnect or reload. Accepted because it fails safe and is rare. Wrong: a person signs in again and saves their key again.
43. **Try again re-sends the saved key through `setCap`.** The button (`jarvis-key-retry`) shows for `unreachable`, `limited` and a key the server has not reported on. Task 4's rule rechecks it, and the limiter bounds it. Wrong: a charged check per click.
44. **No timer on an unconfirmed key.** `src/ui` forbids them. A saved key with no server reading says `Not confirmed by the server yet` and offers Try again; `Checking…` shows only when the server says so. DEPLOY.md makes server-first a hard order, because the wire cannot reveal a server's version. Wrong: copy only.
45. **A socket lost mid-turn is a STATUS entry, not this PR.** It leaves Jarvis's turn open until a reload, but it predates this work and carries no key. Wrong: the same wedge as today.
46. **The key field uses `autocomplete="new-password"` plus the password managers' ignore attributes.** This overrides the plan's `off`. The risk is a login password filled into a field that is forwarded to a provider. Wrong: no cost.
47. **`stop()` also releases the held key, and silence from the server says nothing about the key.** A holder surviving a hot swap, and false copy after a timeout-synthesized availability, were both promoted into the fix wave. Wrong: small.

## PR 4: OpenRouter and OpenAI

48. **The live session's desk gets a direct test of its cancelled-turn guard**, though `jarvis.effects.test.ts` already pins it, because the OpenAI-compatible session builds on the desk. Accepted on the mutation evidence without a scoped re-review, since it adds only a test. Wrong: one weak test.
49. **A broken or hostile provider costs no more than its own turn.** Five review minors were promoted into Task 13's fix round: a cancel during the last iteration ends clean, a request with no response headers in time fails, a reported cost is clamped to a multiple of the request's listed worst case, tool calls per reply are capped (a repeated or missing call id is made unique, a call naming no tool is answered), and a 429's body is read only up to a bound. Wrong: small.
50. **The turn's Effort is not sent to an OpenAI-compatible provider.** The spec's behaviour list does not name effort, and the Effort control is already disabled for brains outside the effort-capable set. Wrong: Effort reads disabled for those brains.
51. **Reasoning is switched off in each provider's config, and no listed model must reason** (the first of the two options carried from Task 13, rather than a per-model `thinks` flag). OpenAI's Chat Completions takes function tools on its current models only with reasoning off, so the field is needed anyway; with reasoning off every output token streams, so a cancelled request booked from what streamed misses nothing. The probe fails a model that reports reasoning tokens. Wrong: a model whose reasoning cannot be switched off cannot be listed until the flag exists.
52. **The models, two per provider, from the providers' docs on 2026-11-02.** OpenRouter: DeepSeek V4.1 Flash (cheap) and Claude Sonnet 5 (strong), both from the models its API marks as supporting tools, reasoning not mandatory. OpenAI: GPT-6 Luna (cheap) and GPT-5.6 Sol (strong); its newer GPT-6.1 Sol and Terra take tools only on the Responses API, and GPT-6 Astra cannot switch reasoning off. The user's probe run decides: a model that fails comes out. Wrong: a model is dropped before merge.
53. **OpenRouter routes only to providers that honour every field** (`provider.require_parameters`), so none can ignore the tools or the reasoning switch. Wrong: fewer providers per model, and an error if none is left.
54. **OpenRouter is still asked for usage** (`usage: { include: true }`). Its docs now say usage comes on every reply and the field has no effect; sending it costs nothing and keeps the cost arriving if that changes. Wrong: a dead field.
55. **The token limit goes under `max_completion_tokens` at OpenAI and `max_tokens` at OpenRouter.** OpenAI's reference marks `max_tokens` deprecated; some OpenRouter models list only `max_tokens`. Wrong: a 400 from one provider, which the probe shows.
56. **The "Your key" row lists only the models the server offers**, which are those of the key's provider, rather than every provider's with the rest disabled. It reads the same as before for an Anthropic key. Wrong: one filter per client.
57. **A preferred own brain of another provider than the key's reads `Scripted · your key is for <Provider>`**, ahead of that key's own trouble (unreachable, limited); a spent own limit still comes first. Wrong: one string.
58. **The full-stack own-key journey is two tests, not one with a longer timeout.** Its CI trace showed sign-out was not slow: the 30 s test budget ran out before sign-out began, with each click after a boot waiting one to three seconds for the page to settle. Each half fits the budget with room. The extra test pushed a quick local run past the server's per-IP login limit, so the suite now logs in once per worker and seeds that token into each test's fresh browser context. Wrong: one more page boot per run, and tests that share one server session.
59. **The probe runs the server's own builder and configs**, reads the key from a file, and prints a refusal's status and error type, never its message. It can show what Anthropic answers a key low on credit only if the key used is one. `AnthropicAgentLoop` gained a `fetchFn` seam for the own-key client, for the probe and tests; the host stays fixed. Wrong: a seam unused in production.
60. **The SSE parser's linear-time test counts characters scanned, not time**, so a loaded runner cannot fail it, and a scan gone quadratic stops at the budget instead of running on. Wrong: the count is a proxy; a rescan through `indexOf` would not show.

### PR 4 final-review fix wave

61. **A refused key is checked again when the same key is sent again**, charged to the guess limiter like any check, and "Try again" shows for `refused`. Out of credit is now the common refusal, and a top-up must be recoverable without Remove. This supersedes items 12 and 18. Wrong: one charged check per click on a key that is still refused, bounded by the limiter.
62. **OpenRouter's 403 for flagged input is not a refused key.** Its body is read up to the same bound as a 429's; an error whose metadata names `reasons` or a `flagged_input` fails the turn with the generic copy. A 403 without them still refuses (OpenRouter also answers 403 for a key over its budget). Wrong: a person whose input is flagged reads the generic copy, not why.
63. **OpenRouter's booked cost is the larger of what it reported and the listed price.** On a key the person keeps at OpenRouter for another provider (BYOK), `usage.cost` is OpenRouter's fee alone and the provider's charge is `cost_details.upstream_inference_cost`, so the two are added; the listed price is the floor, the existing clamp the ceiling. Wrong: a turn on a cheaper endpoint books a little more than it cost.
64. **OpenRouter's requests carry a price ceiling at the listed price** (`provider.max_price`, per model, through a new `modelBody` config field), so a cancel booked at the listed price books no less than any endpoint charges. Wrong: a model with no endpoint at or under the listed price fails every turn; the probe shows it, and the list's price is raised.
65. **One reply's generated characters are capped** (text, and tool-call ids, names and arguments) at four times what the turn's token limit makes at the estimate, and its distinct tool calls at four times the calls a reply may run; past it the request fails through the turn's catch and what streamed is booked. Wrong: a legitimate reply that long is cut off, which the token limit already prevents.
66. **The probe names a refused request only when the turn went wrong**, so a request the SDK retried after an overload or a 5xx passes; and it prints a provider's error type and code as at most 64 printable characters. Wrong: none.
