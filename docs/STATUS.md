- **Fullstack observability & distributed tracing** — **spec merged 2026-08-05, nothing built.** Vendor survey done and decided: **Sentry** as the backend, reached through a repo-owned `ObservabilityPort`, with **W3C Trace Context + OTLP as the wire formats** so the vendor stays an adapter (pre-vetted fallback: Grafana Cloud — 50GB traces, 3 users, no card). Datadog disqualified on cost/lock-in; self-hosted SigNoz rejected as a second production system to operate. **The finding that shaped it: this app is WebSocket-native, and neither Sentry nor OTel auto-instruments WebSockets** — the whole trading path is `WsAdapter` → `ws` → `ws-effects`, so every vendor's out-of-the-box tracing yields page loads and nothing else. Propagation is therefore hand-written into the existing `{ type, payload, correlationId? }` frame as an optional `traceparent`, which makes the vendor choice a backend/cost decision rather than a capability one. **Two numbers drive the design:** `PricingSimulator`'s ~511ms mean tick = ~2 frames/sec/symbol, so **one open tab would exhaust the 5M-span monthly free tier in under four days** if ticks were spanned (hence head-sampling by *frame class* — RPCs and subscribe-handshakes traced 100%, stream ticks never spanned, only metered); and a throw inside a per-frame rAF loop is 60 errors/sec, so **one animation-loop bug would burn the 5,000-error monthly budget in ~83 seconds** (hence a client-side circuit breaker *before* the SDK, not Sentry's server-side spike protection, which bills first). **Sourcemaps resolve without touching the existing flag:** production moves to `sourcemap: "hidden"` — generated, uploaded to Sentry with Debug IDs, then deleted before deploy — so Vercel's 403-on-served-`.map` becomes irrelevant (Sentry symbolicates from its own copy) and the `RTC_SOURCEMAPS=1` inline debug build stays untouched for DevTools profiling. **Already shipped (the one lightweight slice):** server-side WS connection logging (`packages/server/src/observability/connectionLog.ts` — one structured line per accept / disconnect / rejected-upgrade, reason-tagged, token-safe), deployed and verified live on Fly 2026-07-25; all four branches emit, and it doubles as the end-to-end oracle for the auth gate. Note `active`/`total` are per-process, so Fly's idle autostop resets them — "who's connected now" is reliable, lifetime totals are not; that same autostop is why the server adapter needs a **`SIGTERM` flush** or loses everything buffered. See the server README → [Connection observability](../packages/server/README.md#connection-observability). **Six phases, none started:** (1) port + contract + dep-cruiser allowlist *with a falsification test* (dep-cruiser package rules sat dormant until #327, so a negative gate that never runs looks identical to one that passes) + server OTLP + structured logs; (2) web errors + hidden-sourcemap pipeline; (3) the WS distributed trace; (4) Jarvis span tree with token/cost attributes — the only instrumentation with a dollar sign attached; (5) RN (EAS Build auto-uploads sourcemaps, **EAS Update does not** — needs an explicit CI step); (6) optional Session Replay + Fly Prometheus dashboards. **Known constraint: Sentry's free tier is 1 user** — anyone else means the $26/mo Team plan. - **Blank line between adjacent multi-line "block" statements — PARKED (investigated, no rule adopted).** Spun off from the `rtc/newspaper-order` extension (PR #287) that now pushes `jest.mock`/`jest.unmock` below the tests like `vi.mock` (both are hoisted above imports by their runners, so position is behaviour-neutral). The newspaper autofix already *separates* the mocks it moves (it joins them with a blank line), but there is **no rule that enforces a blank line between adjacent multi-line blocks in general** — e.g. two `jest.mock(…, () => {…})` factories authored already-at-the-bottom, packed with no separator. Goal was a *generic, size-based* rule ("if a statement spans more than ~2–3 lines, separate it"), **not** an identifier-based mock-only one. Findings: **(1) Biome cannot do it** — the maintainers deliberately don't implement `padding-line-between-statements`; blank-line *insertion* is classed as formatting, and the Biome formatter only preserves/collapses blank lines, never inserts required ones ([biomejs/biome#3016](https://github.com/biomejs/biome/discussions/3016)). **(2) ESLint can, via the existing `padding-line-between-statements`** (already in `eslint.config.mjs`): the `multiline-expression` selector matches exactly the missing case — multi-line call statements ending in `)` (like `jest.mock(…)` / `describe(…)`) that the current `multiline-block-like` clause misses because they don't end in `}`. Config would be one clause: `{ blankLine: "always", prev: "multiline-expression", next: "multiline-expression" }`. **(3) But its blast radius is large and imprecise** — measured on the repo it flags **350 spots across 152 files** (120 test, 32 production), all autofixable, with two false-positive modes: **(a)** simple statements that merely *wrapped* because they were long (e.g. a 3-line `expect(headers.get("CT")).toBe("application/json")`) get split from the next assertion — same spirit as the "don't separate one-liners" objection; **(b)** production RxJS assignment chains (`this.x$ = src.pipe(…)`) get separated field-by-field. Root cause: no built-in selector expresses *"a call whose **argument** is a real block / object-literal body"* — `multiline-block-like` keys on a trailing `}`, `multiline-expression` on any 2+-line span; the granularity is binary (single- vs multi-line), with no line-count threshold. **Options if revived:** (i) accept the generic `multiline-expression` clause (repo-wide, or scoped to `**/*.{spec,test}.{ts,tsx}` to spare production RxJS) and live with the wrapped-statement noise; (ii) write a small autofixable custom `rtc/` rule that fires only between multi-line statements whose body is an actual block/object-literal (exempting merely-wrapped ones) — precise, matches the "block" intent, but new code to maintain; (iii) do nothing and rely on the newspaper-order autofix for the common (moved-mock) case. **Parked** until it recurs / annoys enough to justify option (i) or (ii).
